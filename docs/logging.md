# Быстрый файловый лог

Лог включён автоматически. Файл `logs/tpc.log` располагается рядом с
активным `settings.json`. Для текущей Release-сборки:

```
.build/release/TPC_Slint.app/Contents/MacOS/Settings/logs/tpc.log
```

Пример формата:

```
2026-10-07T14:00:01.123+0300 [WARN] [field-quality] WARNING: fit residual exceeds configured limit
```

Время фиксируется при поступлении события, не при его записи на диск.
Используются местное время ОС, миллисекунды и смещение часового пояса.
Непечатаемые символы/переносы экранируются: одно событие — одна строка.

Записываются запуск/остановка, подключение OPC UA, изменения настроек,
предупреждения качества данных/поля, ошибки, запуск и завершение расчёта,
построение срезов, сохранение VTK. Пароли, endpoint и поток сырых измерений
не записываются. Неизменившиеся состояния качества подавляются; изменение
и восстановление записываются. Каждая операция расчёта регистрируется отдельно.

## Производительность и пределы

- Один фоновый поток занимается форматированием, записью и ротацией.
  Вызывающий поток только копирует ограниченную запись в очередь под короткой
  блокировкой; файловых операций на UI/OPC UA потоке нет.
- Очередь ограничена 8192 записями, сообщение — 4096 байтами, источник — 64.
  UTF-8 не обрезается посреди символа. При переполнении новые записи отбрасываются;
  количество потерь регистрируется отдельной строкой, а не замедляет UI.
- Flush примерно каждые 250 мс и при штатном завершении. При завершении
  очередь полностью обрабатывается. `fsync` для каждой записи не используется:
  при аварийном завершении/отключении питания последние записи могут потеряться.
- Файл до 5 МиБ, пять архивов `tpc.log.1`…`tpc.log.5` (первый — самый новый).
  Старейший архив автоматически удаляется. Верхняя граница файлов — около 30 МиБ.
  Файл дополняется при следующем запуске, а не стирается.
- При ошибке доступа/диска приложение продолжает работу; ошибка выводится в stderr,
  повторное открытие пробуется не чаще раза в секунду. Потери сообщаются при
  восстановлении или в stderr при остановке. Это диагностический лог, не
  гарантированное долговременное хранилище измерений.
- Один экземпляр приложения должен владеть одним набором файлов. Для параллельных
  экземпляров нужны отдельные пути настроек/логов; межпроцессная ротация не поддержана.

Параметры задаются `LogOptions` в `src/services/logging/async_file_logger.hpp`.
Лог не меняет режим предупреждений: расчёт, слайсы и VTK остаются доступны.

## Проверки

При `TPC_SLINT_BUILD_SCIENTIFIC_TESTS=ON` собирается также `tpc_logging_tests`.
Проверяются параллельные производители, запись очереди при остановке,
таймстампы, экранирование, ограничение сообщений, append при перезапуске,
ротация/лимит архивов, подавление повторов, запись ошибок/операций,
освобождение подписок, отказ файловой системы и учёт переполнения.
