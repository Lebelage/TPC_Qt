# Файлы настроек и выбор датчиков

В **Settings → Configuration file → Open…** можно выбрать JSON-профиль.
Также можно вставить путь в поле и нажать **Load file** или Enter. Строка
**Active** показывает файл, в который **Apply changes** сохранит изменения.
**Reload** перечитывает активный файл. При запуске приложение использует свой
обычный `Settings/settings.json`; выбранный через интерфейс профиль действует
в текущем сеансе.

Загрузка проверяет весь профиль перед заменой текущих настроек. Ошибка JSON,
координат или коэффициентов сохраняет предыдущую конфигурацию. Выбранный файл
не изменяется при открытии и обнаружении датчиков. Новый профиль отключает
предыдущее соединение: нажмите **Connect**, чтобы получить набор датчиков для
его endpoint. Относительный путь к эталонной карте считается от каталога профиля.

Пример профиля (координаты — миллиметры, вход — милливольты):

```json
{
  "coordinate_unit": "mm",
  "geometry": { "length": 4058, "radius": 1408.569 },
  "connection": {
    "endpoint": "opc.tcp://127.0.0.1:1234",
    "polling_interval": 1000
  },
  "grid": [128, 128, 64],
  "sensors_info": [
    {
      "previewable_name": "E1",
      "x": 0,
      "y": 1408.569,
      "z": -2029,
      "enabled": true,
      "calibration": {
        "R": { "k": 0.569788, "v0_mv": -25.37 },
        "F": { "k": 0.747579, "v0_mv": 10.46 },
        "Z": { "k": 0.751044, "v0_mv": -3.22 }
      }
    },
    { "previewable_name": "W1", "enabled": false }
  ],
  "analysis": { "input_in_gauss": false }
}
```

Имена имеют вид `E1`, `W1`, `E12` и т. д.; каждый датчик должен иметь уникальное
каноническое имя. Для доступности сервер должен обнаружить все три канала
`R`, `F`, `Z` (например, `E1R`, `E1F`, `E1Z`). Один отсутствующий канал оставляет
датчик недоступным. Другие имена каналов не добавляются как датчики Холла.

Коэффициенты применяются по формуле `B [G] = k [G/mV] × (U [mV] − v0_mv [mV])`.
Можно переопределить один канал или несколько: для отсутствующих записей
используется встроенная коллекция коэффициентов. `k` должен быть конечным и
ненулевым, `v0_mv` — конечным. Если сервер уже передаёт гауссы, задайте
`analysis.input_in_gauss: true`: повторное преобразование не выполняется.
Неизвестный канал без встроенной и файловой калибровки сохраняет прежний режим
предварительного восстановления с предупреждением о неполной калибровке.

В **Workspace**:

- Найденный датчик с известными координатами включается **ON**, если его
  `enabled` не был сохранён как `false`.
- Снятая галочка исключает весь датчик из следующих восстановлений поля.
  Поток обновлений и повторное обнаружение не сбрасывают ручной **OFF**.
- Датчик из файла, не найденный на сервере или имеющий неполный набор каналов,
  остаётся в таблице красным, **OFF**, с недоступной галочкой.
- Найденный на сервере датчик, которого не было в файле, добавляется в таблицу.
  Для стандартных E1–E6/W1–W6 подставляются известные координаты. Те же координаты
  используются, если в файле указано только имя стандартного датчика.
- Для неизвестного положения показывается **Coordinates required**. Укажите
  в профиле все `x`, `y`, `z` и `position_configured: true` (или удалите это
  служебное поле), затем загрузите файл и подключитесь снова.
- **Apply changes** сохраняет текущий список и пользовательский выбор в активный
  файл. Доступность с сервера и номер версии обновления в файл не записываются.
- Отключение от сервера снимает доступность, сохраняя список и ручной выбор.
  При реконструкции учитывается выбранный доступный набор; фиксированного
  требования ровно 12 датчиков больше нет. Недостаточный ранг по-прежнему
  отражается предупреждением о предварительном восстановлении.

Изменение набора датчиков, геометрии или калибровки делает прошлое восстановление
неактуальным. Для визуализации и экспорта нужно снова нажать **Calculate field**.
