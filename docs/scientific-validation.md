# Научная валидация и оставшиеся пункты ТЗ

## Реализовано

- Расчёт принимает ровно 12 датчиков E1…E6/W1…W6, 36 конечных значений.
  Отсутствующий канал не подменяется нулём. Проверяются статус OPC UA,
  время получения, sourceTimestamp, возраст и межканальный разброс времени.
- Отсутствующая калибровка не блокирует предварительный расчёт по просьбе пользователя.
  При смешанных G/mV результат явно помечается PRELIMINARY; физическая точность
  и соответствие Br/Bz не подтверждаются. Остальные проверки сохранены, включая
  диагностику невязки; до полной калибровки она не имеет единой физической единицы.
  Добавление оставшихся 33
  калибровок отложено. `input_in_gauss=true` допустимо только если сервер уже
  выдаёт откалиброванные Br/Bphi/Bz в G, а не для обхода проверки сырых mV.
  В таблице отображаются также некалиброванные каналы: для них показываются
  исходные mV, для откалиброванных — G. Это не означает допуск к расчёту поля.
- Используется десятимодовый гармонический базис в области без токов.
  Изотропная нормировка координат сохраняет свойства базиса; нормировка столбцов
  матрицы устраняет влияние разных порядков полиномов. SVD-порог 1e-10 —
  численный, не критерий однородности. В интерфейсе неполный ранг выдаёт
  предупреждение; строится предварительное решение минимальной нормы.
- Рассчитываются ранг, обусловленность нормированной матрицы, максимальная
  покомпонентная невязка и RMS. В интерфейсе невязка выше порога выдаёт
  предупреждение, не блокируя срезы и экспорт. Строгий режим API сохранён.
- По сетке объёма оцениваются max |Br/Bz|, max |Btransverse/Bz| и min |Bz|.
  На оси вместо неопределённой радиальной компоненты используется модуль
  поперечного поля. При малом Bz критерий считается неопределённым.
- Исправлены экспорт до расчёта, доступ к карте при пересчёте, ошибки загрузки
  среза и расчёта без подключения. Изменение настроек инвалидирует снимок.
  Снимок не объявляется непрерывно обновляемой картой. Есть бюджет памяти
  и отмена расчёта при остановке фонового потока.
- В синтетическом кадре устранено постоянное смещение Bphi: тестовые значения
  теперь совместимы с регулярным гармоническим полем без токов.
- Некорректный существующий JSON настроек сохраняется, а не заменяется
  автоматически другой геометрией.

## Настройка

Интерактивный расчёт работает в режиме предупреждений: качество OPC UA,
свежесть, согласованность, количество каналов, калибровка, расположение,
ранг и невязка не блокируют конечную предварительную карту. При пропусках
компоненты заполняются нулями с явным предупреждением. Нулевые координаты
не заменяются выдуманными позициями: получается вырожденное решение минимальной
нормы. Его нельзя считать физически достоверной картой. Расчёт, срезы и VTK
доступны независимо от предупреждений. Полное отсутствие данных, NaN/Inf,
некорректная геометрия объёма, бюджет памяти, сбой SVD и ошибки чтения карты
или записи файла остаются техническими ошибками.

В существующий settings.json можно добавить объект (старые файлы совместимы):

```json
"analysis": {
  "maximum_residual_gauss": 0.2,
  "maximum_radial_ratio": 0.00052,
  "minimum_axial_field_gauss": 1.0,
  "maximum_sample_age_ms": 3000,
  "maximum_frame_skew_ms": 1000,
  "input_in_gauss": false,
  "reference_map_path": ""
}
```

Предел 5.2e-4 взят из явного ограничения ТЗ; для более строгой цели 1e-4
нужно изменить параметр. Геометрия и опорная карта в cm, поле в G.
Ориентация датчиков предполагает, что R/F/Z уже приведены к общей цилиндрической
системе TPC; иначе нужны реальные матрицы ориентации и соглашение о знаках.
Положительный Z соответствует E, отрицательный — W.

## Опорная карта

Поддержан внутренний JSON-формат регулярной декартовой сетки:
`coordinate_unit: "cm"`, `field_unit: "G"`, `components: "Cartesian"`,
массивы координат `x`, `y`, `z` и массив `field` из `[Bx,By,Bz]`.
Порядок узлов: X меняется быстрее Y, Y быстрее Z. Пример —
`tests/reference_map.json`. Путь абсолютный. Экстраполяция запрещена.

В датчиках вычисляется ΔB = Bmeasurement − Breference, гармонический базис
аппроксимирует ΔB. В объёме B = trilinear(Breference) + harmonic(ΔB).
Без карты используется самостоятельная гармоническая аппроксимация с явной
пометкой; это не выполнение пункта коррекции ранее снятой карты.
Для вашего фактического формата потребуется образец и подтверждение единиц.

## Что пока НЕ подтверждено и НЕ завершено

1. Отправка на сервер ОИЯИ: нужны endpoint, транспорт, схема сообщения,
   авторизация и требования к подтверждению доставки. Передача на реальный
   сервер, очередь повторов и испытания обрывов пока не реализованы.
2. Температура усилителей 23±0.5 °C: нужны адреса температурных каналов,
   привязка к датчикам, статусы и управление термостатом. Сейчас соответствие
   температурному требованию не проверяется.
3. Абсолютная точность 0.2 G: малая невязка НЕ доказывает точность датчиков
   или интерполяции. Нужны калибровки, неопределённость опорной карты,
   ориентация/позиционирование, температурный бюджет и независимые контрольные
   измерения внутри объёма. Обусловленность диагностируется, но неопределённость
   восстановленного поля пока не распространяется из измерений.
4. Максимум Br/Bz проверяется в узлах сетки, не сертифицируется для каждой
   непрерывной точки. Нужны исследования сходимости/адаптивная оценка экстремумов.
5. Трилинейная интерполяция экспериментальной карты сама по себе не обеспечивает
   div B=0 и rot B=0. Эти ограничения соблюдает гармоническая поправка;
   качество исходной карты должно проверяться отдельно.
6. Источник должен иметь синхронизированные часы и обновлять sourceTimestamp
   даже для постоянного сигнала. Усреднение массива относится к одному
   timestamp сообщения; длительность и синхронность выборки задаёт сервер.
7. Непрерывная эксплуатация пять лет требует реальных тестов связи/перезапуска,
   хранения истории, мониторинга, долговременных испытаний, эксплуатационных
   регламентов. Монтаж, ввод в эксплуатацию и научный отчёт кодом не заменяются.

## Автоматические проверки

```sh
cmake -S . -B .build/release -DTPC_SLINT_BUILD_SCIENTIFIC_TESTS=ON
cmake --build .build/release -j 4
ctest --test-dir .build/release --output-on-failure
```

Проверяются масштабирование, все гармонические моды, div/curl поправки,
невязка, ранг, нечисловые данные, контроль однородности/малого Bz, бюджет памяти,
36-канальный кадр, свежесть/согласованность, интерполяция карты и её коррекция.
Тестовая карта предназначена только для проверки интерполяции, не для магнита.
